## Problem Statement

Hemanth needs to see that AI can turn simple human instructions + real-world footwear references into photorealistic, wearable shoe concepts — as images, not 3D models.

Original PRD (`shoe_ai_mvp_plan.md`) specified Next.js + Three.js + GLB + LLM-to-JSON-to-3D. User pivoted in office-hours:

> "i dont want to make 3d models i want to create the imges my wow movement is the realistic ness of the images and also creatting a new desnins from simple instructions"

Refined wow (engineering):

> "there should a prompt box and a lots of refereces from other brands From other brands. In each brand there are multiple types of shoes so that in each shoe we can extract one key element and combine lots of different elements, then use a custom prompt to generate. That is the main wow moment in the engineering part."

So the core loop is: pick brand shoes → extract 1 key element each → combine N elements + custom prompt → generate new photorealistic designs.

User has Gemini API key (text + image → image). Goal = Hackathon/demo.

## What Makes This Cool

Not another generic text-to-image box. It's a **sneaker mashup lab**:

- "Take the sole from On Cloudmonster, upper knit from Nike Pegasus, luxury minimal palette, make it a college everyday sneaker" → 3 photoreal studio shots in <10s.
- Realism from almost nothing — beginner prompt like "premium everyday sneaker for college that feels sporty but minimal" still yields wearable, correctly-proportioned footwear.
- Fusion is visible and explainable: UI shows which element came from which shoe ("Sole: Hoka exaggerated rocker / Upper: Adidas Primeknit-style technical knit / Vibe: luxury minimal").
- Second-opinion upgrade path: same concept → full Drop Kit (hero 3/4 + on-foot street + top-down tech sheet).

## Constraints

- Image-first MVP. No Three.js, no GLB, no Blender, no local GPU — explicitly out.
- Gemini-only for MVP. Key in hand. Models: `gemini-2.5-flash-image` (MVP default x3, speed/cheap), `gemini-3.1-flash-image` (V2 opt-in: 2K upscale + up to 14 refs, behind flag), `gemini-3-pro-image` (V2-only, out of MVP), fallback `gemini-2.0-flash-preview-image-generation` if 2.5/3.1 unverified via `models.list`.
- Hackathon timebox: must demo in days. Fewest files wins. Trait JSON: 3 entries min to demo, 10 max.
- Key server-side only: Next.js API route, `GEMINI_API_KEY` env, never in browser.
- Inspiration is guidance not cloning: translate Nike/Adidas/On/New Balance/ASICS/Puma/Salomon/Hoka/Converse/Vans into design traits. UI may show "Pegasus-type mesh (inspired by)" — image prompt uses trait-only language ("engineered mesh upper"), never brand names. No logos, no exact trade dress, no "replica" language in prompts.
- Wearability guardrail stays: plausible proportions, real sole/upper/collar/panel logic. "Spaceship" → streamlined aerodynamic styling, not wings/wheels.
- SynthID watermark: all Gemini images carry it. Disclose in demo if asked.

## Recommended Approach

**B (fusion) scoped to A timeline:** ship A shell with B's fusion core.

1. Prompt box + brand/model/element picker (e.g. Nike Pegasus → breathable engineered mesh upper / On → performance rocker sole / Salomon → rugged lugged outsole / luxury minimal → restrained palette).
2. Server builds 3 prompts (safe / balanced / experimental) from selected elements + custom text + wearability guardrail + studio-photo suffix (3/4 view, white seamless, softbox, soft shadow, ultra-detailed).
3. `POST /api/design/generate` fires 3 parallel Gemini calls, returns images + element lineage.
4. Concept tabs (1/2/3) + refine box (`POST /api/design/refine` sends prev image + instruction for multi-turn edit).
5. Download + staged loading ("Analyzing inspiration → Exploring silhouettes → Balancing wearability → Applying materials → Rendering concepts").

Why: maps 1:1 to user's engineering wow, keeps <10s demo, leaves Drop-Kit (C) as explicit fast-follow.

Core data (image-adapted, MVP locked):

```ts
type ArtStyle = 'minimal' | 'luxury' | 'futuristic' | 'retro' | 'streetwear' | 'performance'; // optional, stretch — default ['minimal']
interface DesignRequest {
  prompt: string; // 3..500 chars, required
  elements: { brand: string; model: string; element: string; trait: string }[]; // 1..4 required for MVP
  artStyle?: ArtStyle[]; // stretch, defaults to ['minimal'] if omitted
  referenceInputs?: string[]; // base64 dataURL, V2 only, MVP always []. 14 = max for 3.1, not MVP usage.
}
interface ShoeConcept {
  id: string; name: string;
  imageUrl: string; // dataURL base64 JPEG 1024px base (~300-500KB each) for MVP. 2048px upscale opt-in (stretch). If total >4MB fall back to Blob/hosted URL. Blob storage in V2.
  lineage: string[]; // template from selected elements, e.g. ["sole: rocker sole (Pegasus-type)"]
  summary: string; // first 140 chars of expanded brief, no extra LLM call
}
```

API (standardized on `/api/design/*`):
- `POST /api/design/generate` { prompt, elements[], artStyle? } → { concepts: [{id, name, imageUrl, lineage, summary}] }
- `POST /api/design/refine` { conceptId, imageUrl, instruction } → { conceptId, imageUrl, lineage }
- Error shape: `{error:{code:'SAFETY_BLOCK|RATE_LIMIT|TIMEOUT', message, retryable:boolean}}`
- Validation: elements 1..4, prompt 3..500 chars. Retry 2x on 429/5xx, `Promise.allSettled` + partial render (show 1–2 if third fails). Safety-block → graceful error UI with retry + edit prompt hint.
- Logging per call: model ID, prompt-template version, latency, retry count, safety-block reason.

## Success Criteria

- New user understands product in seconds, studio immediately accessible.
- Can pick 1–4 elements across brands + type simple prompt → 3 visibly different (silhouette/sole/material/color) photoreal concepts.
- Designs remain recognizably wearable; no logos/text artifacts.
- Refine ("gum sole, deep blue accents") updates active concept without resetting session.
- Feels premium, loading communicates progress (states: empty / loading 5-stage / partial-success / error with retry / refine), failures graceful.
- No secret in browser, no Blender/local GPU.
- NFRs: p50 <15s for 3-batch on Flash 2.5 (target <10s), cost logged per call, responsive desktop-first (mobile stretch), no auth/persistence in MVP (history = in-memory session only).
